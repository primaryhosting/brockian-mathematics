# Torus verified-claim surface

The honesty firewall, reaching the public site (`torus.riemannlab.com`). These
files let a lab bind any visual or textual claim to a formally-verified theorem
and render an honest certificate badge — or a distinct **BLOCKED** state when the
claim is not backed.

## The honesty contract

1. **A picture cannot show a claim the registry does not back.** Every visible
   claim binds to a fully-qualified theorem name. If that name is not in the
   public verified registry, the claim renders as **⊘ UNVERIFIED** (red,
   visually distinct) — never a verified badge.
2. **Sanitized surface only.** The public registry (`verified-registry.json`) is
   produced by `scripts/export_public_registry.py`, which strips internal ledger
   notes, provenance notes, quarantine internals, and file paths. The site never
   sees them.
3. **Sources are never merged.** Counts are split by source
   (`brockian` / `mathlib` / `physlean`). A headline count never mixes
   "we proved" (brockian / AXLE) with "we indexed".
4. **A proof is a proof; a conjecture is not.** `PROVED`, `DEFINITION`, and
   `DISCHARGED` render as verified. `CONDITIONAL` (open premise) and
   `CONJECTURE` render as distinct **not-a-proof** states, never green.

## Files

| File | Role |
|---|---|
| `public/verified-registry.json` | Sanitized public registry, generated by the exporter (do not hand-edit). |
| `useVerified.ts` | Hook: resolves a theorem name → certificate record or `null`. Tries `GET /api/verified/search?name=…`, falls back to the static JSON. Memoized. |
| `VerifiedClaim.tsx` | Component: renders the certificate badge or the BLOCKED state. |
| `manifest.schema.json` | JSON Schema for a lab manifest binding claims → theorem names. |

## Regenerating the public registry

From the repo root:

```bash
python3 scripts/export_public_registry.py
# writes torus/public/verified-registry.json and prints the kept/stripped
# field report + the split-by-source summary + an honesty self-check.
```

Re-run it whenever `registry/theorems.json` changes, and republish the resulting
`verified-registry.json` with the site.

## Dropping these into the torus Lovable project

The torus site is React + Tailwind + shadcn. These files are self-contained
(only React + the hook); no extra UI libraries are needed.

1. **Copy the component + hook** into the Lovable `src` tree, e.g.
   `src/components/verified/VerifiedClaim.tsx` and
   `src/components/verified/useVerified.ts` (keep them side-by-side so the
   relative import `./useVerified` resolves).
2. **Publish the registry as a static asset.** Copy
   `torus/public/verified-registry.json` to the site's `public/` folder so it is
   served at `/verified-registry.json` (the hook's fallback path). In Lovable,
   add it under `public/`.
3. **(Optional) wire the live search API.** If a backend exposes
   `GET /api/verified/search?name=<theorem>` returning a record (bare,
   `{result}`, or `{results:[…]}`), the hook prefers it and uses the static file
   only as a fallback. No config needed — the endpoint path is fixed.
4. **Author a lab manifest** validated against `manifest.schema.json` and render
   each binding:

   ```tsx
   import { VerifiedClaim } from "@/components/verified/VerifiedClaim";

   // from the lab manifest
   <VerifiedClaim
     claim="Exactly 5 admissible residues mod 5"
     theorem="Brockian.Admissibility.admissibility_count_five"
   />

   // an unbacked claim renders BLOCKED automatically:
   <VerifiedClaim
     claim="The Riemann Hypothesis is true"
     theorem="Brockian.Nonexistent.rh_is_true"
   />
   ```

5. **Verify the BLOCKED path in the preview.** Point one `VerifiedClaim` at a
   theorem name that is not in the registry and confirm it renders the red
   **⊘ UNVERIFIED** badge — that is the firewall working.

## Accessibility

`VerifiedClaim` is keyboard-focusable (`tabIndex=0`), carries a descriptive
`aria-label` for both verified and BLOCKED states, uses `role="note"` (and
`role="status"` while loading), and styles both light and dark themes with a
visible focus ring. Color is never the only signal — a glyph (`✓`, `⊘`, `◇`, …)
and a text label always accompany it.

02 — For the seL4 ecosystem

A concrete contribution, not just our own models

seL4 the kernel is proven; the systems built on it are not. Its isolation guarantee is conditional on the initial capability layout — described by capDL, what microkit and CAmkES compile to — and nothing in the toolchain formally checks that a given layout enforces the intended isolation. A single mis-wired capability silently breaks it.

A verified capDL isolation checker

A decidable checker with a machine-checked soundness-and-completeness proof: a true verdict is a formal certificate that a system's capability distribution confines every subsystem to its protection domain — including transitive isolation (an isolated domain is unreachable through any capability chain).

03 — Trust

Independent verification is the moat, not the theorem count

Generating a candidate proof is now cheap. The entire locus of value is verification and trust — and the failure modes AI introduces are not false proofs (the kernel catches those) but valid proofs of subtly wrong statements, and empty files with grand names.

Nine imports-only files scored as "passing proofs" of famous problems under a naive no-sorry check. That failure taxonomy — and the gate that enforces it — is what a high-assurance org needs before it lets AI near its proofs.

The gate every theorem passes

  • Independent re-verification — a proof only counts if a second prover (AXLE) agrees.
  • Axiom audit — no native_decide, no sorryAx; only the trusted kernel axioms.
  • Statement fidelity — checked against the intended claim, not merely "it compiles".
  • Provenance tiers — verified · conditional · unverified render distinctly; nothing ambiguous.

Multi-prover, already working

Three properties — a bitvector one-time-pad involution, a boolean default-deny law, an array-theory write frame — are discharged by Z3 and Lean/AXLE on identical statements, with agreement required.

05 — Boundary

The honest limits

Ecosystem

seL4 is Isabelle; you are SAW / Cryptol / Coq; we are Lean / AXLE. Our value is multi-prover orchestration and trust — not a claim that Lean subsumes these. A real engagement builds the bridge.

The spec is human

AI verifies; it does not tell you what "correct" means. Statement fidelity is a permanent human responsibility, and a verified kernel is only as good as its spec.

Trust bootstrapping

Who verifies AXLE, or the SMT solver? Real high-assurance answers this with proof-producing solvers and a small trusted kernel; our gate must eventually verify itself.

Implementation is years

We can build the verified mathematics of a secure kernel now and accelerate the proof engineering; a running verified kernel down to binary is seL4-scale.
